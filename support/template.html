Agent design system · living template

Document template & component showcase

Every HTML document built for the user — spec companions, debriefs, reports — uses these tokens and components. This page renders each one live so new documents copy working source, not prose descriptions. If a document doesn't look like this showcase, it's off-template.

How to use this file. Open it in a browser to see every component in both themes. View source to copy — the whole page is built from its own rules. Each section also ends with a collapsed Source block holding minimal, canonical markup for copy-paste. Copy the <style> block once per document; take component markup per section.

Rules

  • Self-contained. Everything inline; the file opens from disk. The only allowed external dependency is the Mermaid CDN script, and only on pages that actually contain Mermaid diagrams.
  • One accent. Notion blue for links/emphasis/new; amber for decisions and risks; green for done; red only for hard failures. No gradients, no new colors, no display fonts.
  • Borders over shadows. Hairlines and 8px rounding define surfaces; shadows only on floating elements (tooltips).
  • Icons are inline SVG stroking currentColor — never icon fonts or CDNs. Visual texture on headings, statuses, and cards; no screenful of pure text.
  • Calm motion. Nothing autoplays; movement is direct feedback to the reader's own interaction. Honor prefers-reduced-motion.
  • Every document defines its jargon with .term hover definitions, keyboard-focusable.
  • Prose at 720px; tables and diagrams may take .wide; mini worlds take .fullbleed (full height, dot-grid, fullscreen toggle) — never the prose column.
  • System views match ~/.pi/agent/packages/portable-pi-setup/support/examples/ — atlas (where does it live?), metro (what changes?), lifecycle (what happens over time?). A bland box-and-arrow substitute is below the bar.
  • Both themes, always. Every color is a token; verify light and dark before shipping.

Canon prose lives in ~/.pi/agent/packages/portable-pi-setup/support/html-template.md; this file is the rendered proof. When a new pattern earns its place, add it here and keep this page the best example of itself.
